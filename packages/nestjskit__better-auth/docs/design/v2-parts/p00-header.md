## How to read this document

**Provenance tags.** Every design element names the draft(s) it came from: `[A]`, `[B]`, `[C]`, `[L]` for a change the lead made during the v1 merge, and `[R1:<finding id>]` for a change made in response to review round 1 (for example `[R1:SEC-r1-01]`). A bare `[R1]` marks a table row or paragraph whose finding ids are given inline, and `[R1:<reviewer> decision]` marks a change that answers a reviewer's proposed user decision rather than a finding (§17.1). The decision log (section 16) records the alternatives rejected and why; the review ledger (`ledger.md`) records every finding and its resolution. `v1` and `v2` always mean design versions; library releases are written `1.0` and `1.x`.

**LEAD-EXP-2** (`tmp-revise-v2/exp-fastify-child-errhandler.cjs`, Nest 11.1.17 and 12.0.1 × `NestFactory` and `@nestjs/testing`, Fastify 5.8.2/5.12.1, global prefix `v1`) `[R1:NEST-r1-04]`. An encapsulated auth plugin registered with `await` in `onModuleInit` sets a child error handler that reads `root.errorHandler` **at request time**. Result on all four runs: a throwing auth handler reached the app's `APP_FILTER` (status 599 written by the filter); an over-limit body answered the canonical `413 { code: 'PAYLOAD_TOO_LARGE' }` with the root `onRequest`-set CORS header preserved; a controller error still reached the filter.

**LEAD-EXP-3** (`tmp-revise-v2/exp-coordinator-last-arrival.cjs`, Nest 11.1.17 and 12.0.1) `[R1:NEST-r1-02, NEST-r1-03]`. A coordinator that records the adapter from `init$` and receives platforms from a provider behind an **async** dependency calls `prepare()` when both are known. `NestFactory.create`: `init$ → platforms registered → prepare → create() resolved → init()`. `@nestjs/testing`: `platforms registered → compile() resolved → init$ → prepare → createNestApplication() returned`. `createApplicationContext` and `createMicroservice`: `init$ adapter=null → skip`, no throw.

**LEAD-EXP-4** (`tmp-revise-v2/exp-node-fetch-headers.mjs`, Node 22.22.0) `[R1:SEC-r1-01]`. A server-side `fetch` POST carries `sec-fetch-mode: cors` and **no** `Origin`, `Referer` or `Sec-Fetch-Site`.

**LEAD-EXP-5** (`tmp-finish-v2/exp5/`, TypeScript 5.9.3, 6.0.3 and 7.0.2 × `nodenext` ESM, `nodenext` CJS, `bundler`, `node16` CJS). A fake package with this design's exports map keeps `PrincipalKinds` in a shared declaration chunk that the root entry re-exports. Its `./api-key` declaration file augments the **root specifier by package self-reference** (`declare module '<own name>' { interface PrincipalKinds { 'api-key': … } }`). Result on all 24 runs: a consumer that imports `./api-key` gets `'api-key'` in `PrincipalKind` and narrowing on `p.kind`; a consumer that imports only the root does not. Negative control: with the augmentation pointed at a wrong module name, the consumer fails to compile while the package's own declarations stay silent under `skipLibCheck`, so only a consumer fixture can catch a broken augmentation (§12.9 step 10).

**LEAD-EXP-6** (`tmp-finish-v2/drizzle/probe.mjs`, Node 24.14.1; constructor copied verbatim from drizzle-orm 0.45.2 `errors.js:10-19`) `[R1:SEC-r1-08]`. A `DrizzleQueryError` has the enumerable own properties `query`, `params` and `cause`. Wrapped as a `cause`, `util.inspect` prints the query parameter (a session token) twice: once in the message and once in `params`. After scrubbing `message` and `stack` **in place** it still prints it once, and a JSON serializer over the error's own properties prints it once as well. A redacted cause therefore has to be a new error built from an allow-list of fields (§13.4, ADR-43).

**LEAD-EXP-7** (`tmp-close-gaps-r2/exp7/probe2.mjs`, `probe3.mjs`; Node 24.14.1, @apollo/server 4.13.0, Mercurius 16.10.0 on Fastify 5, graphql 16.14.2; `NODE_ENV` production and development) `[R1:SEC-r1-19]`. A resolver throws an error that no transport mapped, as a param decorator does when the guard did not run. With the detail in `message`, both drivers send the handler name and the hint to the client in `errors[0].message`, in both modes. With a fixed generic `message`, the detail and hint in ordinary own properties (`detail`, `hint`, `code`) and `extensions: { code, reason, statusCode }`, neither driver sends the detail or the hint; both copy `extensions` (Apollo adds its own `stacktrace` in development, whose header line is the generic message). `util.inspect`, which Nest's logger uses (LEAD-V31), prints the enumerable `detail` and `hint`.
