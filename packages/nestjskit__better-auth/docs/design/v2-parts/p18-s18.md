## 18. Changelog

- **v2.0** (2026-09-11 to 2026-09-17), lead architect. Revision after review round 1. The three reviewers (BA: better-auth fidelity; NEST: NestJS correctness, packaging, SOLID; SEC: security and operations) all rejected v1, with 43 findings: 4 blockers, 19 majors and 20 minors. All 43 were accepted; one in a modified form (SEC-r1-17), and three are duplicates of others (SEC-r1-09, SEC-r1-10, SEC-r1-12). `ledger.md` has the resolution of each, §16 the decisions (ADR-34 to ADR-53 are new, 30 older ones were revised), and §17 the questions and risks that came out of it.
  - **Who may call what (blockers).**
    - better-auth's origin rule now covers every operation that an ambient cookie authenticated: unsafe HTTP methods, GraphQL mutations, every WebSocket message and subscription. It uses better-auth's own trusted origins, matcher and disable flags (§7.10, ADR-34) `[SEC-r1-01, BA-r1-03]`.
    - Principal kinds are admitted per route (`kinds`, `acceptance`, `@AcceptPrincipals`, kinds named by requirements). Delegated principals (API keys, OAuth tokens) are never widened beyond their own grant: invariant Z5 and `PrincipalDelegation` (§7.6, §8.1, ADR-35) `[BA-r1-01, SEC-r1-02]`.
    - Authorization decisions are memoized per handler invocation (`TransportCall.invocation`), never per request or connection. Policy I/O is deduped by concrete inputs, and `@ActiveOrganizationId()` is per invocation (§7.2, ADR-37) `[NEST-r1-01]`.
  - **Authorization details.**
    - The admin `permission()` reads identity authoritatively by default (`requires.freshIdentity`), so a banned admin is locked out at once, as on better-auth's own admin endpoints (§8.4, ADR-36) `[SEC-r1-04]`.
    - better-auth's 400 `user not found` is a 401 `USER_NOT_FOUND`, no longer a 500 `[BA-r1-10]`.
    - Connection-level principal entries hold only `authenticated` and `absent` `[SEC-r1-13]`.
  - **Cookies and the plugin.**
    - `Set-Cookie` of application direct `auth.api` calls is no longer forwarded by default. Forwarding is opt-in (`@ForwardAuthCookies()`, `cookies.forwardDirectCalls`, `service.forwardCookies`) and limited to calls that carry the caller's own credential or none (§7.5, ADR-48) `[BA-r1-02, SEC-r1-03]`.
    - The client-IP header name is random per plugin instance (ADR-44) `[SEC-r1-18]`. The plugin counts dispatches made before binding (B26, ADR-53) `[NEST-r1-11]`. The bridge protocol is version 2.
  - **API keys** (§8.3.1, ADR-42).
    - A result-mapping table for `verifyApiKey`: 429 with `Retry-After`, 401, or 5xx. A throttled outage probe, the `references` option for organization-owned keys, and declared `effects` `[BA-r1-04, SEC-r1-05, SEC-r1-14]`.
    - The `enableSessionForAPIKeys` quota multiplier is documented, tested and announced as boot advice by the session unit, triggered by the api-key plugin's presence (`session.apiKeySessions` states the unreadable option) `[BA-r1-05]`.
  - **Lifecycle and HTTP platforms.**
    - A last-arrival mount coordinator replaces platform selection inside the `init$` replay, and a `null` adapter means "no HTTP" (§5.7, ADR-38) `[NEST-r1-02, NEST-r1-03]`.
    - The Fastify auth scope has a child error handler: failures reach Nest's filters, and the 413 body is the canonical one (§6.4.2, ADR-39; H4 and H8 tightened) `[NEST-r1-04]`.
    - `onAPIError.throw` is honored (ADR-50; H13 added) `[BA-r1-09]`.
    - Platforms report proxy trust; B27 and `W_PROXY_UNTRUSTED` make the two silent misconfigurations visible (§6.8; H12 added) `[SEC-r1-06]`.
    - A production boot without a `baseURL` fails: B23 (ADR-46) `[SEC-r1-07]`.
    - Unknown paths under the mount get a "did you mean" log line outside production (ADR-52) `[SEC-r1-16]`.
    - `betterAuthCorsOrigin` uses the post-init trusted set and exact origins by default (§6.9, ADR-33) `[BA-r1-11, SEC-r1-17]`.
  - **Surfaces the guard cannot reach fail boot** (ADR-40): every gateway on every Nest major, with the version probe removed `[NEST-r1-13, SEC-r1-12]`; hybrid-RPC handlers without `inheritAppConfig` `[NEST-r1-05, SEC-r1-09]`; GraphQL field resolvers that carry requirements `[NEST-r1-06, SEC-r1-10]`.
  - **Open-closed.**
    - Core names no extension: `definePrincipalParam`, `defineInvocationParam`, a generic `NO_TRANSPORT`, and `advise()` on every contract (B21). The session unit and `httpTransport()` moved to `src/extensions/**` (ADR-41) `[NEST-r1-07]`.
    - Platforms and transports are declared once, on the default instance (B25), and `ExtensionDefinition.exports` provides `WsConnectionAuth` under `WS_CONNECTION_AUTH` (ADR-45) `[NEST-r1-09, NEST-r1-12]`.
    - Named instances must not share cookie names: B24 (ADR-47) `[SEC-r1-11]`.
  - **Hooks and types** (§10, §11, ADR-49). Database hooks are mirrored per operation, with types derived from `BetterAuthOptions['databaseHooks']`; throwing matchers propagate `[BA-r1-06]`. The claim about what before-hooks can see was corrected and the banned-user example replaced `[BA-r1-07]`. Hook bodies are `UnvalidatedBody` `[BA-r1-08]`.
  - **Errors and logging** (§13, ADR-43). Infrastructure errors carry a redacted cause, with the raw one behind `errors.exposeRawCause` `[SEC-r1-08]`. Request-time internal errors are generic on GraphQL (`toInternalException`, `BetterAuthGraphqlInternalError`), and request-time configuration errors are generic as thrown (`BetterAuthConfigurationError.atRequest`), which covers the param decorators that throw where the guard did not run (§7.8, LEAD-EXP-7) `[SEC-r1-19]`.
  - **Testing** (§14, ADR-51). `overrideAuthGuard` covers both guard registrations and `stampPrincipal()` is public; both publish through a test stamp that the scope interceptors copy into the scope, so replaced guards work on WebSocket gateways too (§7.8, LEAD-V34) `[NEST-r1-08]`. `initTestApp` closes the previous test app, and a binding whose app never bootstrapped is taken over: B06, ADR-25 `[SEC-r1-15]`. New conformance cases: `T-invocation-decisions`, `T-acceptance`, `T-csrf-*`, `T-ws-origin-untrusted`, `T-subscription-origin`, `T-internal-error-generic`, `S-apikey-*`, `S-bridge-*`, `S-log-redaction`, `S-delegation`, `Z-delegation-*`, `Z-admin-*`, `Z-per-invocation`, `Z-apikey-quota-per-request`, `H-async-options-factory`, `H-no-adapter`, `H-errors-apierror-throw`, `H-limit-canonical-body`, `H-proxy-trust`, `H-diagnostics-404`, and the repository tests `LIB-hook-bearer-client`, `LIB-cors-helper`, `LIB-testing-override-principal` and `LIB-testing-stamp-mock-guard` (§14.5, §14.8). The matrix gained the 11.2.x line, the adapter-less bootstraps, and the hybrid-RPC and GraphQL coverage jobs.
  - **Naming.** `@Session()` became `@CurrentSession()` (ADR-24) `[NEST-r1-10]`.
  - **Boot checks.** B04, B06, B08, B14, B15, B16, B19, B21 and B22 changed; B23 to B28 are new (§5.4).
  - **Migration guide** (§15). Five new checklist steps (proxy trust, `baseURL`, API-key routes, direct-call cookies, server-side callers that forward cookies), and the behavior changes that follow from the items above.
  - **Packaging** (§12). The plugin's allowed imports are `better-auth/api`, `better-auth/cookies` and `defu`, with Web Crypto and no `node:*`. §12.4 lists the better-auth specifiers the package imports, checked at the 1.7.0 floor, and the Nest-owned identifiers, with no deep imports and no version probing. §12.5 states where every piece of per-application state lives and adds `Symbol.for` brands for the library's own error classes. §12.9 lines up with §14 (identifier pins per Nest major, the adapter-less tarball fixture, consumer types across better-auth versions and with or without `./api-key`).
  - **Decision log and questions.** ADR-34 to ADR-53 added, and 30 ADRs revised with the findings that forced each change. Q13 to Q17 record the reviewers' proposed user decisions; Q18 to Q20 record three more that the lead decided. RK18 to RK26 added; RK13, RK14 and RK15 re-rated; RK9 and RK11 rewritten; RK1, RK3, RK5 and RK10 extended with the v2 surfaces. Q2, Q4, Q6, Q8 and Q12 updated for the v2 defaults. Q1, Q8, Q9, Q11 and RK4 write the first release as `1.0`, so `v1` only ever names design v1.
  - **Verification.** LEAD-V16 to LEAD-V35 (source re-checks) and LEAD-EXP-2 to LEAD-EXP-7 (LEAD-V34, LEAD-V35 and LEAD-EXP-7 come from closing the gaps a post-revision audit found). The reviewers' experiments were re-run where they decided an action. Two facts surfaced while finishing the revision:
    - better-auth's own origin rule gained the `Origin: null` + `Sec-Fetch-Site: same-origin` inference only in 1.7.2, so the mirrored rule already differs from the router at the D4 floor (LEAD-V33, RK20; the origin test became a differential one, §14.5);
    - scrubbing an error's message in place is not enough, because Drizzle keeps the query parameters in an enumerable property (LEAD-EXP-6).
  - **Consistency fixes of the finishing pass.** `normalizeThrown` passes the library's own, already classified errors through (§13.2), which §7.3 and §8.3.1 relied on. Once-per-process wording became once-per-application, because the library keeps no module-level state (§12.5). Draft-internal ids in §16 are written `B-Qn`, so they cannot be mistaken for this document's ids.
- **v1.0** (2026-09-11), lead architect. First merged design, built from drafts A ("better-auth-native"), B ("ports and adapters") and C ("DX and types first").
  - **Adopted from A:**
    - Fastify encapsulated `parseAs: 'buffer'` parser with native 413;
    - the `ExtensionDefinition` registration helper;
    - scope interceptor plus explicit internal scopes;
    - the carrier stamp;
    - `defu`-based dispatcher parity;
    - `getActiveMemberRole` membership proof;
    - the separate plugin build;
    - named instances via `AuthOf<N>`;
    - the Hono two-phase sketch.
  - **Adopted from B:**
    - ports-and-adapters layering with the architecture fitness tests;
    - the `PrincipalResult` union ("denials are values");
    - invariant tables mapped to conformance ids;
    - policies resolved by reference through `ModuleRef`;
    - deferred-413 Express drain;
    - exclusive binding;
    - the `withUpgradeRequest`-style mixin;
    - `WsConnectionAuth`;
    - the experiment log E1–E11.
  - **Adopted from C:**
    - the type layer (`DefaultInstanceCheck`, the required `customSession` mapper, `BetterAuthFactoryResult`, `EndpointPath`, typed hook contexts, permission types becoming `never` without the plugin);
    - aggregated boot diagnostics with "did you mean";
    - no hook class marker, and `'model.op'` DB hook targets;
    - `defaultAccess`;
    - the plan compilation rules and `readsSession`;
    - a two-level `code`/`reason` error payload;
    - authoritative reads as a plan attribute;
    - unbinding in `onApplicationShutdown`;
    - the Nest-major capability probe for gateway coverage.
  - **Lead changes [L]:**
    - GraphQL denials as an `IntrinsicException` subclass (LEAD-EXP-1 showed B's approach loses the 429 code under Apollo and A/C's approach logs every denial);
    - param decorators read the interceptor scope first, because WS param factories cannot see the per-message key and the socket races (LEAD-V7);
    - the platform-scope rationale was corrected, since body-parser preserves ALS (LEAD-V11);
    - the Express/Fastify accessor gained `responseFor` for Apollo on Fastify (LEAD-V8);
    - `orgMember()` corrected to `getActiveMemberRole` semantics (403 `YOU_ARE_NOT_A_MEMBER_OF_THIS_ORGANIZATION`);
    - LEAD-V1–V15 source verifications.
  - **Resolved contradictions:**
    - plugin mandatory (A, C) vs optional (B) → mandatory;
    - module name `AuthModule` (C) vs `BetterAuthModule` (A, B) → `BetterAuthModule`;
    - platform auto-detection (C) vs explicit (A, B) → explicit;
    - hooks including internal calls (A, C) vs excluding them (B) → including;
    - WS default revalidation per message (A, C) vs 300 s (B) → per message;
    - policy registry by kind (A) vs by reference (B, C) → by reference;
    - multi-app hook routing (A) vs exclusive binding (B, C) → exclusive;
    - one instance (B) vs named instances (A, C) → named;
    - method-level `@Public` fail-closed (A) vs opt-out (C) → opt-out, with Q3;
    - GraphQL error type (A/B/C) → `IntrinsicException` subclass.
