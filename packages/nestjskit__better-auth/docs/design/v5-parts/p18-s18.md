## 18. Changelog

- **v5.0** (2026-09-17), lead architect. Revision after review round 4. All three reviewers rejected v4, with 15 new findings (0 blockers, 6 majors, 9 minors); every round-3 finding, and the three round-2 findings round 3 had marked unresolved, were marked resolved. All 15 were accepted. The three user decisions the reviewers proposed are applied as each reviewer recommended and recorded as open questions (Q35 to Q37). `ledger.md` has the resolution of each, §16 the decisions (ADR-69 and ADR-70 are new, 22 older ones were revised), and §17 the questions and five new risks. Two mechanisms were replaced rather than patched: the plugin no longer becomes inert at shutdown (a closed binding keeps its hooks), and the admin policy no longer copies the stored role (better-auth's endpoint reads it).
  - **Owner decisions.** The owner answered §17 Q13 to Q34 on 2026-09-17, each with the recommended option. §17.1 now separates the open questions (Q35 to Q37, §17.1.1) from the decided ones (§17.1.2, each marked "Decided by the owner on 2026-09-17: the recommended option", with its options and recommendation kept) and from the v1-merge questions (Q1 to Q12, §17.1.3). The header, §0.4 and §1 say so. The design already applied every recommendation, so no mechanism changed because of the answers.
  - **Shutdown and the plugin** (§5.7, §10.2, §10.6, ADR-31, ADR-25, ADR-53).
    - `onApplicationShutdown` closes a binding instead of unbinding it; a closed binding keeps dispatching the application's Nest hooks until another application binds, so work that a global module drains later in the same shutdown (a BullMQ worker) cannot skip a `@BeforeDatabase` rule. Inert remains the state of a plugin that was never bound. `BridgeHandle.bound`/`unbind()` became `state`/`close()`, and the protocol is version 4 `[SEC-r4-01]`.
    - One plugin object serves one instance: B03 fails boot with `PLUGIN_SHARED_BETWEEN_INSTANCES` when two instances resolve the same handle, and `bind()` throws for a second instance of the same owner `[BA-r4-05]`.
  - **Security.**
    - A direct `auth.api` call that carries the caller's session cookie, in a handler scope whose unsafe browser leg carries a cookie and has no passing origin verdict (a `@Public()` handler), fails with `PUBLIC_HANDLER_USED_CALLER_SESSION`: the scope interceptor supplies `ScopeView.checkCallerSession`, and plugin before-hook entry 2 runs it. The check only reads the guard's verdicts. Migration maps such `@AllowAnonymous()` handlers to `@OptionalAuth()` (§7.5, §15, ADR-70, §17 Q37) `[SEC-r4-02]`.
    - The GraphQL units fail boot for a context object (`GRAPHQL_STATIC_CONTEXT`), and the HTTP branch requires `HttpRequestAccessor.isLive` where implemented (`GRAPHQL_CONTEXT_STALE_REQUEST`), so a context shared across requests can no longer authenticate every caller as the first one (§9.2, ADR-61) `[SEC-r4-03]`.
    - The re-classification read of a generic 401 is shared per logical request in the policy I/O memo and counted against the authorization budget, so an outage costs one read and one ERROR line per request, not one per alias (§8.1, ADR-59, ADR-68) `[SEC-r4-04]`.
    - Origin-denial WARN lines use an hourly window with a summary line instead of a lifetime cap, and a `Referer` is logged as its origin (§7.10, ADR-34, ADR-52) `[SEC-r4-05]`.
  - **GraphQL.**
    - Federation: `@ResolveReference()` handlers are entry points, never nested, claimed with `everyHandler` (`REFERENCE_RESOLVER_UNGUARDED`); federation subgraphs with field or reference resolvers require field guards (`FEDERATION_FIELD_GUARDS_REQUIRED`), both at `federationCoverage` (default `'error'`, §17 Q36); each representation is its own invocation, with positions per entity type; an inheriting handler whose lineage holds no enclosing reading fails with `NO_ENCLOSING_DECISION` instead of serving data (§9.2, §7.1, ADR-69, ADR-40, ADR-56, ADR-66) `[NEST-r4-01]`.
    - Inherit plans take the nearest enclosing reading whatever its instance, and a nested public plan records nothing, so what a nested reader sees no longer depends on the instance of the shared field resolver or on `fieldResolverEnhancers` (`RoutePlan.nested`, §7.8, ADR-64) `[NEST-r4-03]`.
    - A `subscriptionCredentials` override keeps the upgrade request's `host`, `x-forwarded-host` and `x-forwarded-proto` unless it sets them, and invariant T5 requires them for every credential mapping of a transport that makes no host-less calls (§9.2, ADR-60) `[BA-r4-03]`.
  - **better-auth fidelity.**
    - The admin policy calls `userHasPermission({ body: { userId, permissions } })` without a role, so better-auth reads the stored user and applies `defaultRole` and `adminUserIds` itself; a NULL role (every user that predates `admin()`) no longer answers 500. The delegated path passes the row's role only when it is a non-empty string; the endpoint's 400 `user not found` maps to 401 `USER_NOT_FOUND` (§8.3, ADR-36, ADR-13, §17 Q29's mechanism) `[BA-r4-01]`.
    - B30 `W_RATE_LIMIT_DISABLED` warns when better-auth's rate limiter is off in a deployment the library treats as production without `NODE_ENV=production`; the boot summary prints the limiter's state, and B18, B27 and `W_PROXY_UNTRUSTED` stop describing rate-limit buckets while it is off (§5.4, §6.8, ADR-67, §17 Q35) `[BA-r4-02]`.
    - The JWT-source sketch verifies with jose over the instance's JWKS and lets key-fetch and storage errors throw, because `verifyJWT` reports them as invalid tokens (§4.3.4, ADR-13, RK18) `[BA-r4-04]`.
  - **Coverage and planning.**
    - B16 recognizes the global guard and interceptor by identity with what their class tokens resolve to, overrides included; the brand is only the fallback for the other package copy, so `overrideProvider(BetterAuthGuard)` and `overrideAuthGuard()` boot again (§5.4, §5.7, §12.5, ADR-40, ADR-51) `[NEST-r4-02]`.
    - `PrincipalSource.delegates` makes delegation static data, and B15 counts a policy without kinds as admitting exactly the non-delegating sources' kinds, so a kind-less company policy in `defaultRequirements` next to API-key routes fails boot (§4.3.1, §5.4, ADR-35, ADR-58) `[NEST-r4-04]`.
  - **Testing.** §2.2.16 and §14.8 list the admin policy among those that need real data under `overridePrincipal`, and `LIB-testing-override-decisions` pins 401 `USER_NOT_FOUND` for a fixed principal without a stored user (ADR-51) `[NEST-r4-05]`.
  - **Observations on earlier findings.** `slowMs` must stay below the pool's smallest lock or statement timeout, which §8.3.1 and RK18 now say `[SEC observation on SEC-r3-01]`; `T-ws-origin-forwarded-host` states the trust-proxy setting its unset-`baseURL` HTTP row needs `[SEC observation on SEC-r3-02]`; coded 401s that mean "no session" deny 403, which §8.1 and RK2 now record `[BA observation on BA-r3-01]`.
  - **Contracts.** `BridgeHandle.state` and `close()` replace `bound` and `unbind()`, `BridgeBinding` gained `instance` and a lifecycle `state`, and the bridge protocol is version 4; `ScopeView` gained `checkCallerSession`; `RoutePlan` gained `nested`; `PrincipalSource` gained `delegates`; `HttpRequestAccessor` gained `isLive`; `GraphqlTransportOptions` gained `federationCoverage`; `AuthContextView` gained `rateLimit` and `options.rateLimit`; `PrincipalReading.instance` now names the instance whose guard run recorded the reading, which for an inherit plan is the enclosing one. Invariants H10, T5, T6, T7, T8, T10, P5 and Z2 were rewritten; units U1, U2, U7 to U11, U13 and U16 (§3.1) were updated.
  - **Boot checks.** B03 (shared plugin object), B04 (protocol 4), B06 (closed bindings taken over silently), B15 (kind-less policies), B16 (identity recognition; the federation codes), B18 and B27 (wording while the limiter is off), B20 (the GraphQL and WS units declare no host-less calls), B21 (`W_FIELD_RESOLVER_INHERITS` counts public reference resolvers), B22 (the limiter's state) and B26 (only dispatches before the first binding) changed; B30 (`W_RATE_LIMIT_DISABLED`) is new. New codes: `PLUGIN_SHARED_BETWEEN_INSTANCES`, `REFERENCE_RESOLVER_UNGUARDED`, `FEDERATION_FIELD_GUARDS_REQUIRED` and `GRAPHQL_STATIC_CONTEXT` at boot; `NO_ENCLOSING_DECISION`, `PUBLIC_HANDLER_USED_CALLER_SESSION` and `GRAPHQL_CONTEXT_STALE_REQUEST` at request time.

- **v4.0** (2026-09-17), lead architect. Revision after review round 3. All three reviewers rejected v3, with 23 new findings (0 blockers, 12 majors, 11 minors), and marked three round-2 findings unresolved (NEST-r2-06, NEST-r2-07, SEC-r2-02). All were accepted; SEC-r3-04 with the reviewer's second option (the per-call-site forwarding switch is removed rather than given its own origin check). `ledger.md` has the resolution of each, §16 the decisions (ADR-64 to ADR-68 are new, 28 older ones were revised), and §17 seven more lead-decided questions (Q28 to Q34) and two new risks. Three mechanisms were simplified rather than patched: v3's six ways to read a principal became one lookup, the gateway heuristic became a canary, and the per-call-site forwarding switch was removed.
  - **Reading the principal** (§7.8, ADR-64, ADR-57) `[NEST-r3-01, NEST-r2-06, NEST-r3-02, NEST-r2-07]`.
    - The carrier map by memo key, its exactly-one rule and the readers' `peek()` are gone. The guard records each reading on the invocation and at its lineage position (the GraphQL response path), and every reader uses one lookup: public plans read no identity, inheriting field resolvers the nearest enclosing invocation's reading, other plans their own. A nested field can no longer read a sibling root field's principal or fail depending on scheduling.
    - `principalFor(ctx)` is total: `'no-identity'` on public plans, and `PRINCIPAL_READ_BEFORE_GUARD` instead of `undefined` in a guard that runs before `BetterAuthGuard`, such as an `APP_GUARD` declared in `AppModule`. B16 counts a `BetterAuthGuard` the app registers itself, and the boot summary prints the global guard order.
  - **Planning** (§7.6).
    - A single `PolicyResolver` resolves policy references before plans compile, so a DI policy's instance-level `requires` (kinds, `freshIdentity`) reaches its plans (ADR-65) `[NEST-r3-04]`.
    - Class-level access, acceptance and requirements apply to operation handlers; GraphQL field resolvers inherit unless they carry method-level metadata (ADR-66) `[NEST-r3-05]`.
    - `@SkipDefaultRequirements()` and B15 `UNSATISFIABLE_PRINCIPAL_KINDS` make `defaultRequirements` composable with machine routes (ADR-58) `[NEST-r3-06]`.
  - **better-auth fidelity.**
    - Only the generic 401 (no code, or `UNAUTHORIZED`) is re-classified, and only for principals from a session-backed source; coded 401s deny 403; `customSession` apps answer 401 for a policy-path outage, as documented (§8.1, ADR-59) `[BA-r3-01, BA-r3-05]`.
    - The admin policy passes the stored user row's role, never a `customSession` shape's (§8.3, ADR-36) `[BA-r3-02]`.
    - The API-key probe is keyed on the `key` column, type-safe under every `generateId` mode, and `verifyApiKey` receives the forwarding headers better-auth reads for a dynamic base URL (§8.3.1, ADR-42, ADR-60) `[BA-r3-03, BA-r3-04]`.
    - The `orgSlug` hint maps slugs through `listOrganizations` (§8.3, ADR-63) `[BA observation on BA-r2-08]`.
  - **Security.**
    - The origin check trusts a leg's own origin only for an unset `baseURL`, and `upgradeRequestUrl()` reads no forwarding headers, which closes a socket hijack through `X-Forwarded-Host` on socket.io's polling handshake (§7.10, ADR-34) `[SEC-r3-02]`.
    - Origin denials are logged at WARN once per reason and origin, and the session unit advises about native clients when the `expo()` plugin meets the strict default (§7.10) `[SEC-r3-03]`.
    - A slow `INVALID_API_KEY` counts as infrastructure, so a lock on the key's own row no longer answers 401; the probe's coverage claim is corrected (§8.3.1, RK18, RK31) `[SEC-r3-01, SEC-r2-02]`.
    - `service.forwardCookies(fn)` is removed; forwarding is declared where the guard applies the form-CSRF rule, and `forwardForeignCookies(fn)` serves account switching inside such handlers (§7.5, ADR-48) `[SEC-r3-04]`.
    - GraphQL contexts take the HTTP branch only when their request is positively the platform's (`HttpRequestAccessor.isRequest`); unrecognized contexts fail with `GRAPHQL_CONTEXT_UNRECOGNIZED` (§9.2, ADR-61) `[SEC-r3-05]`.
    - The delegated admin path denies keys of banned owners (§8.3, ADR-36) `[SEC-r3-06]`.
    - Production is assumed unless `NODE_ENV` names development, dev or test; B19 reports effective skip flags, including vitest's `TEST=true`; B29 rejects better-auth's default secret in production (§5.4, ADR-67) `[SEC-r3-07]`.
    - An infrastructure error is logged once per logical request, and distinct authorization calls per request are budgeted (§8.1, §13.4, ADR-68) `[SEC-r3-08]`.
  - **Lifecycle and coverage.**
    - The lifecycle state belongs to the application that owns the container and is reset at shutdown; a second application from one compiled `TestingModule` is prepared again on Fastify and fails with `APP_ADAPTER_CHANGED` on Express (§5.7, ADR-62) `[NEST-r3-03]`.
    - `UNGUARDED_AUTH_METADATA` has a closed trigger list that leaves hook providers alone (B16) `[NEST-r3-07]`.
    - Boot canaries check every Nest-owned metadata literal on the installed Nest and replace the gateway class-claim heuristic (B16, §12.4) `[NEST-r3-08]`.
    - Both GraphQL units handle every `'graphql'` context and check the driver at boot (§9.2) `[NEST-r3-09]`.
    - `RoutePlan.routeParams` is replaced by transport-supplied inputs in claims (§4.2.1, ADR-41) `[NEST-r3-10]`.
  - **Contracts.** `TransportCall.carrier` became `lineage` (`InvocationLineage`); `AuthTransport` gained `lineage()` and `toInternalException`'s `repeated` flag; `ClaimOptions` gained `inputs`; `BootAdviceContext.plans` became `handlers` (`AdvisedHandler`), and `BootAdviceContext` gained `originCheck`; `HttpRequestAccessor` gained `isRequest`; `HttpPlatform.capabilities` gained `prepareAtInit`; `PrincipalSource` gained `sessionBacked`; `PrincipalResolver` lost `peek`, and `ResolutionRequest.bypassMemo` became `reclassify`; `BetterAuthService.principalFor` returns `PrincipalReading`, and `forwardCookies` became `forwardForeignCookies`; `RoutePlan` lost `routeParams` and gained `declares` and `skipsDefaultRequirements`; `AuthContextView` gained `secret` and `internalAdapter.findUserById`; `ApiKeyPrincipalOptions.outageProbe` takes `{ slowMs }`; new runtime option `limits.maxAuthorizationCallsPerRequest`, decorator `@SkipDefaultRequirements()` and class `BetterAuthGraphqlRepeatedInternalError`. The plugin protocol is unchanged (3).
  - **Boot checks.** B14 (resolution before planning), B15 (`UNSATISFIABLE_PRINCIPAL_KINDS`; class level not for nested handlers), B16 (global enhancers from `ApplicationConfig`, closed trigger list, canaries), B18, B19 (effective flags), B21 (new advice codes), B22 (skip count, environment, guard order), B23 and B27 (production now includes an unset `NODE_ENV`, like B18, B19 and B23) changed; B29 (`DEFAULT_SECRET`) is new. Request-time codes `PRINCIPAL_READ_BEFORE_GUARD`, `FORWARDING_NOT_DECLARED`, `GRAPHQL_CONTEXT_UNRECOGNIZED` and `APP_ADAPTER_CHANGED` are new.
  - **Conformance and tests.** New cases: `H-accessor-is-request`, `H-reused-testing-module` (invariant H14), `T-ws-origin-forwarded-host`, `T-internal-error-logged-once`, `T-metadata-canary`, `T-unsatisfiable-kinds`, `S-session-backed` (invariant P7), `Z-admin-custom-session-role`, `Z-class-policy-requires`, and the repository tests `LIB-apikey-probe-id-modes`, `LIB-apikey-row-lock` and `LIB-environment`. Rewritten: `T-stamp-per-plan` (lineage, both enhancer settings, both settle orders). Extended: `T-selection`, `T-memo-once`, `T-csrf-login-proxy` (the `loginProxyService` fixture), `T-subscription-origin`, `T-inherit-no-lookup`, `T-coverage-claims`, `S-apikey-outage`, `S-dynamic-base-url`, `S-bridge-foreign-credentials`, `Z-apierror-mapping`, `Z-policy-session-lost`, `Z-admin-banned`, `LIB-coverage-rule`, `LIB-origin-differential`, `LIB-principal-for` and the planner, evaluator and lifecycle unit tests. Invariants T1, T6, T8, T9, T10, H10 and Z2, Z5 were rewritten. The kits' better-auth instances set `disableOriginCheck: false` explicitly. The matrix gained storage (PGlite `generateId` modes, a Postgres row-lock job) and environment axes, and the WS, hybrid, HTTP-coverage and GraphQL jobs gained v4 cases.
  - **Verification.** LEAD-V43 to LEAD-V50 (source re-checks: 401 shapes, `customSession`'s catch, `userHasPermission`'s stored-role read and the ban rule, id conversion under `generateId: 'serial'`, trusted origins for dynamic and unset base URLs, `isTest()` and the default secret, `init$` completion and `deferInitialization`, `PARAM_ARGS_METADATA`) and LEAD-EXP-11 (`tmp-r3-revise/`, better-auth 1.7.4 and 1.7.0: 401 classification, the stored role against `listUsers` for three `customSession` shapes, the ban rule, API-key latency and the `key`-column probe). The reviewers' experiments decided every finding with a reproduction; LEAD-EXP-11 re-ran the inputs of the new mechanisms.
- **v3.0** (2026-09-17), lead architect. Revision after review round 2. All three reviewers rejected v2, with 34 new findings (3 blockers, 13 majors, 18 minors) and one round-1 finding still unresolved (SEC-r1-01, for WebSockets and subscriptions). All were accepted; four in a modified form (BA-r2-08: no slug ref, because the only slug lookup writes; NEST-r2-06: an invocation stamp plus a single-entry carrier rule instead of decorators computing memo keys they cannot know without DI; SEC-r2-04: public handlers get no identity instead of a lazily origin-checked one; SEC-r2-09: resolved through inheritance plus a warning). `ledger.md` has the resolution of each, §16 the decisions (ADR-54 to ADR-63 are new, 25 older ones were revised), and §17 seven more lead-decided questions (Q21 to Q27) and three new risks.
  - **Blockers.**
    - An authoritative identity read accepts only a session the get-session endpoint produced, observed by a new plugin after-hook, so an API key's mocked session (`enableSessionForAPIKeys`) no longer passes `@RequirePermission` with its owner's role; the session source tolerates the missing `Headers` of a short-circuited dispatch (§7.3, ADR-54) `[BA-r2-06, BA-r2-01]`.
    - Route plans are cached per (controller class, handler), because Nest shares inherited handler functions between subclasses (§7.6, ADR-55) `[NEST-r2-01]`.
    - The origin check has no explicit-credential exemption: any cookie on an unsafe or WebSocket browser leg needs a trusted origin, whatever `handshake.auth` or `connectionParams` hold, as on better-auth's routes; core keeps no scheme list (§7.10, ADR-34) `[SEC-r2-01, NEST-r2-13, SEC-r1-01]`.
  - **Coverage and planning.**
    - Coverage is one core rule over handler claims that transports supply; a forgotten transport or `globalGuard: false` can no longer leave written requirements unenforced; explicit coverage needs guard and interceptor; `'websockets:message_mapping'` is pinned and cannot pass vacuously (B16, ADR-40) `[NEST-r2-02, NEST-r2-11, NEST-r2-12]`.
    - The guard reads the plan before choosing a transport, so public handlers (other than form-checked login proxies) work in any context and credential-less RPC messages get 401, not 500 (§7.1, §9.4, ADR-55) `[NEST-r2-03]`.
    - GraphQL field resolvers without their own metadata inherit their root field's decision (`defaultAccessFor`), and `W_FIELD_RESOLVER_INHERITS` points at field resolvers reachable from public root fields (§9.2, ADR-56) `[NEST-r2-04, SEC-r2-09]`.
    - `defaultRequirements` replaces the `planFor` subclass seam, and the guard's runtime param-kind check is gone (§7.6, ADR-58) `[NEST-r2-08]`.
    - The principal memo key uses a content key for the source set; the stamps hold each invocation's own result plus an operation-wide map by memo key with a single-entry rule (§7.2, §7.8) `[NEST-r2-16, NEST-r2-06]`.
  - **Reading the principal.** `BetterAuthService.principalFor(ctx)` serves guards and interceptors; `getPrincipal()`/`getSession()` never resolve, return `null` on public plans and throw `NO_AUTH_SCOPE` outside a handler scope; principal param decorators lost `instance` (§7.8, ADR-57) `[NEST-r2-07, SEC-r2-04, NEST-r2-14]`.
  - **better-auth fidelity.**
    - A 401 that escapes a policy is re-classified by one authoritative re-resolution, so storage failures swallowed by better-auth's session middleware answer 5xx, not 403 (§8.1, ADR-59) `[BA-r2-03]`.
    - Units declare host-less server calls, and a dynamic `baseURL` without `fallback` fails boot when one does (B20, ADR-60) `[BA-r2-05]`.
    - The DB update dispatcher returns only what hooks returned (§10.6) `[BA-r2-02]`; `@AfterAuth('/get-session')` rules are scoped to Nest routes (§10.4) `[BA-r2-07]`; the client-IP header's interaction with better-auth's `trustedProxies` is documented and warned (§6.8, B18) `[BA-r2-04]`.
    - Organization refs resolve to validated IDs, the default ref included, with tuple memo keys; no slug ref ships (§8.3, ADR-63) `[BA-r2-08, SEC-r2-06]`.
    - The admin policy lost its `'role'` and `'cached'` modes (ADR-36).
  - **Security.**
    - GraphQL operations are classified by carrier: queries and mutations over graphql-ws or Mercurius `fullWsTransport` are cookie-less and origin-checked like subscriptions (§9.2, ADR-61) `[SEC-r2-03]`.
    - The API-key outage probe adds a no-op write (§8.3.1) `[SEC-r2-02]`.
    - WebSocket browser legs have absolute URLs, and the origin verdict is computed once per leg (§7.10) `[SEC-r2-05]`.
    - Authoritative plans never reuse a connection's principal (§7.2) `[SEC-r2-07]`.
    - Handlers with `@ForwardAuthCookies()` get better-auth's form-CSRF rule, public ones included, and B16 requires a guard to reach them (§7.10, §5.4) `[SEC-r2-08]`.
  - **Lifecycle and tests.** The core module's lifecycle work runs once per application and a same-owner `bind()` is a no-op (`NestMicroservice.init()`); an adapter that never emitted counts as none, and a late one fails with `LATE_HTTP_ADAPTER` (§5.7, ADR-62) `[NEST-r2-05, NEST-r2-09]`. B26 counts database writes (§10.2) `[NEST-r2-10]`. `POLICY_INVOKER` (a core-module provider) and `overrideDecisions` let tests stub policies, and `overridePrincipal` answers the 401 re-classification read `absent`, so an unstubbed organization requirement denies 401 (§14.8) `[NEST-r2-15]`. The better-auth pre-release job targets the newest version inside the peer range (§14.2) `[BA-r2-09]`.

- **v2.0** (2026-09-11 to 2026-09-17), lead architect. Revision after review round 1.   - **Who may call what (blockers).**
    - better-auth's origin rule now covers every operation that an ambient cookie authenticated: unsafe HTTP methods, GraphQL mutations, every WebSocket message and subscription. It uses better-auth's own trusted origins, matcher and disable flags (§7.10, ADR-34) `[SEC-r1-01, BA-r1-03]`.
    - Principal kinds are admitted per route (`kinds`, `acceptance`, `@AcceptPrincipals`, kinds named by requirements). Delegated principals (API keys, OAuth tokens) are never widened beyond their own grant: invariant Z5 and `PrincipalDelegation` (§7.6, §8.1, ADR-35) `[BA-r1-01, SEC-r1-02]`.
    - Authorization decisions are memoized per handler invocation (`TransportCall.invocation`), never per request or connection. Policy I/O is deduped by concrete inputs, and `@ActiveOrganizationId()` is per invocation (§7.2, ADR-37) `[NEST-r1-01]`.
  - **Authorization details.**
    - The admin `permission()` reads identity authoritatively by default (`requires.freshIdentity`), so a banned admin is locked out at once, as on better-auth's own admin endpoints (§8.4, ADR-36) `[SEC-r1-04]`.
    - better-auth's 400 `user not found` is a 401 `USER_NOT_FOUND`, no longer a 500 `[BA-r1-10]`.
    - Connection-level principal entries hold only `authenticated` and `absent` `[SEC-r1-13]`.
  - **Cookies and the plugin.**
    - `Set-Cookie` of application direct `auth.api` calls is no longer forwarded by default. Forwarding is opt-in (`@ForwardAuthCookies()`, `cookies.forwardDirectCalls`, `service.forwardCookies`) and limited to calls that carry the caller's own credential or none (§7.5, ADR-48) `[BA-r1-02, SEC-r1-03]`.
    - The client-IP header name is random per plugin instance (ADR-44) `[SEC-r1-18]`. The plugin counts dispatches made before binding (B26, ADR-53) `[NEST-r1-11]`. The bridge protocol is version 2.
  - **API keys** (§8.3.1, ADR-42).
    - A result-mapping table for `verifyApiKey`: 429 with `Retry-After`, 401, or 5xx. A throttled outage probe, the `references` option for organization-owned keys, and declared `effects` `[BA-r1-04, SEC-r1-05, SEC-r1-14]`.

  - **Lifecycle and HTTP platforms.**

    - The Fastify auth scope has a child error handler: failures reach Nest's filters, and the 413 body is the canonical one (§6.4.2, ADR-39; H4 and H8 tightened) `[NEST-r1-04]`.

    - Platforms report proxy trust; B27 and `W_PROXY_UNTRUSTED` make the two silent misconfigurations visible (§6.8; H12 added) `[SEC-r1-06]`.
    - A production boot without a `baseURL` fails: B23 (ADR-46) `[SEC-r1-07]`.
    - Unknown paths under the mount get a "did you mean" log line outside production (ADR-52) `[SEC-r1-16]`.
    - `betterAuthCorsOrigin` uses the post-init trusted set and exact origins by default (§6.9, ADR-33) `[BA-r1-11, SEC-r1-17]`.
