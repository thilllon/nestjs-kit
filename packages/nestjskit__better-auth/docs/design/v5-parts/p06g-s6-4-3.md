#### 6.4.3 Degraded tier (documented, warned once) `[A][C]`

If a platform finds the stream already consumed before its capture point, it falls back in this order (`recoverConsumedBody`, §2.2.10):

1. `req.rawBody` (a Buffer): exact.
2. `req.body` re-serialized for its content type, with `JSON.stringify` or `URLSearchParams`: lossy.

- **The limit still holds.** Recovered bytes reach `binding.handle()` as a `Uint8Array`, and core re-checks `byteLength > bodyLimit` (§6.3 step 1). An over-limit body therefore still gets the canonical `payloadTooLarge()` Response (H4), even though the host's own parser already read it.
- **A one-time warning** (`W_BODY_ALREADY_CONSUMED`) names the cause and the endpoints that break: raw-signature webhooks such as Stripe's, which read `ctx.request.text()` (R:ba-integrations §4). "One-time" means once per application: the flag lives in the platform provider, because the library keeps no module-level state (§12.5).
- **Trigger.** The only known trigger is an Express instance passed to `new ExpressAdapter(app)` that already had `express.json()` attached before `NestFactory.create`. It never happens in the default setup. Phase A runs inside `NestFactory.create()`, even when the options factory awaits an async dependency (§5.7, LEAD-EXP-3), so it is ahead of everything Nest or `main.ts` registers `[R1:NEST-r1-03]`. Fastify cannot reach this tier, because the auth scope owns its content-type parsers (§6.4.2).

#### 6.4.4 Why buffer instead of streaming to better-auth `[A][B]`

Buffering bounded bytes gives:

- a deterministic 413 before better-auth runs, byte-identical on every platform (H4);
- a correct `content-length`;
- no `duplex: 'half'` stream plumbing;
- no half-consumed stream when a before-hook short-circuits.

With a streaming body and an in-flight limit, better-auth logged `SERVER_ERROR: PAYLOAD_TOO_LARGE` before the host could answer (EXP-B:E4). better-auth's endpoints take small bodies; the largest legitimate ones are SAML responses and SCIM documents, well under 1 MiB (§17 Q5).
