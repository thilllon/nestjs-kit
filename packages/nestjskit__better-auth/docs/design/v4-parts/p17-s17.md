## 17. Open questions and residual risks

### 17.1 Open questions for the user (genuine product trade-offs, each with a recommendation)

The design already applies every recommendation below, so answering "as recommended" changes nothing. Q1–Q12 come from the v1 merge. Q13–Q20 are the user decisions the round-1 reviewers proposed, de-duplicated; Q21–Q27 are the ones the round-2 reviewers proposed `[R2]`; Q28–Q34 are the ones the round-3 reviewers proposed `[R3]`:

- **Q13–Q17** are product trade-offs the lead did not want to settle alone. Each names the reviewer who raised it. **Q15 is one place where the design's default differs from that reviewer's recommendation.** Q16 was reworded in v3, because v3 removed the cheaper admin modes its first option offered (ADR-36).
- **Q18–Q20** were decided by the lead in v2 (D3 delegates naming, ADR-40 sets the fail-closed stance, and an app has one HTTP adapter). They are listed so that the user can overrule them before 1.0.
- **Q21–Q27** were decided by the lead in v3, each with the reviewer's recommendation next to the lead's. **Q21 and Q27 differ from the proposing reviewer's recommendation**; the others apply it.
- **Q28–Q34** were decided by the lead in v4, the same way. **Q29 extends the proposing reviewer's recommendation** (the stored role for every app, not only `customSession` apps), and Q32 prints the global guard order at boot where the reviewer proposed a warning; the others apply the recommendation as proposed.
