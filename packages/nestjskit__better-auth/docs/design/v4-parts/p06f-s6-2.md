### 6.2 Path resolution (S3) `[A][B][C]`

```ts
async function resolveMountPath(auth: AuthLike, allowRoot: boolean): Promise<string> {
  const ctx = (await auth.$context) as AuthContextView;
  const raw = ctx.baseURL
    ? new URL(ctx.baseURL).pathname                 // static baseURL (incl. BETTER_AUTH_URL): its path wins over basePath
    : ctx.options.basePath || '/api/auth';          // unset or dynamic { allowedHosts }: ctx.baseURL === '' (EXP-B:E11)
  const path = raw.length > 1 ? raw.replace(/\/+$/, '') : raw;
  if (!path.startsWith('/') || (path === '/' && !allowRoot)) throw new BetterAuthConfigurationError('INVALID_MOUNT_PATH', …);
  return path;
}
```

- The router uses exactly `new URL(ctx.baseURL).pathname` for a static `baseURL` (`BA/api/index.ts:280`; `BA/utils/url.ts:73-89`).
- For an unset or dynamic `baseURL`, the per-request base path is `options.basePath || '/api/auth'` (`BA/auth/base.ts:51`). EXP-B:E11 verified every configuration style.
- `auth.options.basePath` is **never** read. It is `undefined` by default and wrong when `baseURL` contains a path (R:ba-core §3.7).
- **When it runs** `[R1:NEST-r1-02]`. `MountCoordinator` resolves the path in `onModuleInit`, once per instance, and only when the app has an HTTP adapter and the instance's `http.mount` is not `false`. Adapter-less bootstraps (`createMicroservice`, `createApplicationContext`) never resolve or mount anything (§5.7). B10 then checks the result across instances: no overlapping mounts, and no `Symbol.for(…:mounted)` stamp for the same path on the server.
- **An unset `baseURL` is a development-only configuration** `[R1:SEC-r1-07]`. In the `ctx.baseURL === ''` branch the _path_ is static, but better-auth derives the _origin_ of its base URL from each request, and with it token links and a trusted origin (`BA/auth/base.ts:76-100`). A client-chosen `Host` header then ends up in password-reset links (REV-SEC:`probe-unset-baseurl.mjs`). In production that configuration fails boot (B23 `UNSAFE_BASE_URL`), unless `baseURL` is a dynamic `{ allowedHosts }` config, which better-auth validates per request, or the user sets `http.allowRequestDerivedBaseURL` (§6.3 step 2).
- **Matching** is a raw-string prefix test on the undecoded pathname of the original URL, with the query stripped: `p === base || p.startsWith(base + '/')`. It uses no Express or path-to-regexp wildcard syntax, which broke the reference seven times (R:ref-issues cluster 1). Everything below the prefix goes to better-auth, which owns 404, method checks and trailing-slash rules. An unknown path under the prefix is therefore a bodiless better-auth 404, the largest misconfiguration cluster in the reference's issues. The response stays as it is, and outside production core logs the path once with a "did you mean" (§6.3 step 7) `[R1:SEC-r1-16]`.
- **Precedence.** A Nest controller route that exactly matches a path under the base path is served by Nest on every platform (H11), and B17 warns about it at boot.
- **All methods** are routed, including PUT/PATCH/DELETE (SCIM, oauth-provider), HEAD and OPTIONS. better-auth answers HEAD and OPTIONS with 404 unless host CORS answered the preflight first (R:ba-core §3.1; ADR-32).
