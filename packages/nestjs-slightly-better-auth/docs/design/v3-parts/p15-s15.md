## 15. Migration guide sketch from @thallesp/nestjs-better-auth

Target: apps on `@thallesp/nestjs-better-auth` 2.x (the v2.8.0 surface, R:ref-impl). This is a clean break (D3). Most changes are mechanical renames, and several of the old library's "requirements" disappear. A few deliberate security changes need one decision each (steps 8–14).

### 15.1 Checklist

1. Upgrade better-auth to `>=1.7.0` and Node to `>=22.12`.
2. `pnpm add nestjs-slightly-better-auth`, then remove `@thallesp/nestjs-better-auth`.
3. In `auth.ts`, add the plugin **last** and delete the empty hook placeholders:
   ```ts
   import { nestjs } from "nestjs-slightly-better-auth/plugin";
   export const auth = betterAuth({
     /* … */ plugins: [admin(), organization(), nestjs()],
   }); // no hooks: {} / databaseHooks: {}
   declare module "nestjs-slightly-better-auth" {
     interface Register {
       auth: typeof auth;
     }
   }
   ```
   With several better-auth instances, give each a distinct `advanced.cookiePrefix` (boot check B24).
4. In `main.ts`, delete `bodyParser: false`. Nest's parsers, `rawBody: true` and body limits work again, and auth routes still get raw bytes. Configure CORS on the host. For app routes use an explicit allow-list of the browser origins that may read them. For the auth mount you may follow better-auth's exact trusted origins, scoped to the mount (§6.9):
   ```ts
   // Express (the cors package's per-request options delegate): one CORS middleware, two policies
   const authOrigin = betterAuthCorsOrigin(auth); // exact trusted origins; allowPatterns for wildcards
   app.use(
     cors((req, cb) =>
       cb(null, {
         origin: isUnder(req.path, "/api/auth")
           ? authOrigin
           : ["https://app.example.com"], // helper on the auth mount only
         credentials: true,
       }),
     ),
   );
   // Fastify: the same split in an @fastify/cors delegator keyed on the request path
   ```
   Do not apply the helper app-wide: every exact entry of `trustedOrigins`, including partner origins listed only for `callbackURL`, would gain credentialed read access to every route (§6.9).
5. Replace the module: `BetterAuthModule.forRoot({ auth, platforms: [expressPlatform()] })`, or `fastifyPlatform()`. Platforms and transports go on the default instance only.
6. Rename decorators and move role checks to permissions (§15.2). `@Session()` becomes `@CurrentSession()`. Then remove the `UserSession<typeof auth>` and `AuthService<typeof auth>` generics.
7. Register non-HTTP transports: `apolloTransport()`, `mercuriusTransport()`, `socketIoTransport()`, `wsTransport()` or `rpcTransport()`. Then close the coverage gaps; boot fails until you do (B16):
   - add `@UseBetterAuth()` to every gateway, on Nest 11 and 12 (a plain `@UseGuards(AuthGuard)` becomes `@UseBetterAuth()`, not `@UseGuards(BetterAuthGuard)`: gateways need the scope interceptor too);
   - in hybrid apps, pass `{ inheritAppConfig: true }` to `connectMicroservice` and assert it with `rpcTransport({ inheritAppConfig: true })`, or decorate message controllers;
   - set `fieldResolverEnhancers: ['guards']` in GraphQL if field resolvers carry requirements. Undecorated field resolvers inherit their root field's decision and cost no auth I/O (§9.2);
   - with `disableGlobalAuthGuard` migrated to `globalGuard: false`, add `@UseBetterAuth()` to every controller whose routes declare something (B16: access other than `@Public()`, acceptance, requirements, principal or invocation params, or direct-call forwarding, which includes a `@Public()` login proxy with `@ForwardAuthCookies()`); boot names the ones you missed (`ROUTE_UNGUARDED`). `defaultRequirements` alone does not make an undecorated route need the guard. A forgotten transport shows up as `UNGUARDED_AUTH_METADATA` `[R2:NEST-r2-02, SEC-r2-08]`.
8. **Proxy trust.** Behind a load balancer, set Express `app.set('trust proxy', <hops>)` or Fastify `trustProxy` to the real number of hops. Never set it to `true` in production. The boot summary prints the setting; B27 and `W_PROXY_UNTRUSTED` point at both misconfigurations (§6.8).
9. **`baseURL`.** Set `baseURL` (or `BETTER_AUTH_URL`) in production. A production boot without one fails with `UNSAFE_BASE_URL` (B23), because better-auth would otherwise build reset links from the client's `Host` header.
10. **API keys.** Mark routes that machine clients call with API keys: `@AcceptPrincipals('session', 'api-key')` or an API-key requirement (`@RequireApiKeyPermission`). Keys are no longer accepted on every route, and never judged by their owner's admin role unless a requirement opts in (§7.6, §8.3).
11. **Direct `auth.api` calls that must set cookies** (a custom login or logout controller): add `@ForwardAuthCookies()`. Other direct calls no longer write cookies to the caller's response (§7.5).
12. **Server-side callers that forward browser cookies** on unsafe requests (SSR servers, BFFs): send a trusted `Origin` header, or mark those routes `@SkipOriginCheck()` (§7.10). The same holds for browser clients on another origin that send the API's cookie **and** a bearer token: add their origin to better-auth's `trustedOrigins` (§17 Q26) `[R2:SEC-r2-01]`.
13. **Custom guards that read `request.user`**: read the principal with `BetterAuthService.principalFor(ctx)` (§7.8). `getPrincipal()` throws outside a handler scope, and returns `null` in `@Public()` handlers; handlers that want the session when present use `@OptionalAuth()` `[R2:NEST-r2-07, SEC-r2-04]`.
14. **Company-wide requirements** that a subclassed guard used to add: `defaultRequirements: [orgMember()]` in the module options (§7.6) `[R2:NEST-r2-08]`.
15. Boot the app once. The diagnostics (B01–B28) point at every remaining mistake with a fix.
16. Re-run your e2e tests with origin checks **on** (§14.4).

### 15.3 Role names without the old `@Roles`

The preferred path is to model roles as access-control statements (`createAccessControl`) and use `@RequirePermission`. For teams that need role names now, a custom policy takes a few lines. It follows better-auth's storage format (comma-joined, **no trimming**) but deliberately does not replicate `adminUserIds`/`defaultRole`, so the choice stays explicit in application code (§17 Q1):

```ts
export const hasRole = definePolicy<{ roles: string[] }, "session">({
  id: "app:has-role",
  requires: { plugins: ["admin"], principals: ["session"] },
  evaluate: ({ roles }, ctx) => {
    const userRoles = String(
      (ctx.principal.session.user as { role?: string | null }).role ?? "",
    ).split(","); // no trim, like better-auth
    return roles.some((r) => userRoles.includes(r))
      ? allow()
      : deny({ reason: "MISSING_ROLE" });
  },
});
export const RequireRole = (...roles: string[]) =>
  Require(hasRole({ roles }, { freshIdentity: true })); // authoritative, like admin
```

### 15.4 Behavior changes to verify after migrating

- **Refreshed session cookies now reach the browser on ordinary routes.** This fixes a latent expiry drift. CDN and proxy rules keyed on the absence of `Set-Cookie` should be reviewed.
- **Direct `auth.api` calls in handlers no longer write cookies** unless the handler opts in with `@ForwardAuthCookies()` (the reference never forwarded them either; v1 of this design did).
- **Cookie-authenticated unsafe requests need a trusted `Origin`**, on app routes, GraphQL mutations and WebSocket handshakes, exactly as on better-auth's own routes. Browsers send it automatically; SSR servers and scripts that forward cookies must add it.
- **API keys and other delegated credentials are accepted only where a route asks for them.**
- **`@RequirePermission` reads identity authoritatively** (one storage read per request on such routes, even with the cookie cache). Bans and revocations take effect immediately, also on TTL sockets. There is no cheaper mode, and API keys turned into sessions by `enableSessionForAPIKeys` are rejected there, as on better-auth's admin endpoints.
- **`@Public()` no longer attaches a session.** Handlers that read `@CurrentSession()` on public routes need `@OptionalAuth()`, and B15 tells you which ones. `BetterAuthService.getSession()` returns `null` in a public handler.
- **Cookie-carrying unsafe requests need a trusted `Origin` even when they also carry a token**, and login or logout proxies with `@ForwardAuthCookies()` get better-auth's form-CSRF rule.
- **Authorization infrastructure failures are now 5xx, not 403**, including the ones better-auth's session middleware reports as 401 (§8.1), and a store that reads but cannot write no longer turns valid API keys into 401s. Monitoring may see new 5xx where 403s used to hide outages. Their causes are logged with credentials redacted.
- **Nest hooks can now short-circuit or rewrite input.** A hook that returned an object "for logging" now short-circuits the endpoint.
- **Path-less hooks still see the guard's `/get-session` calls**, as in better-auth. Use `skipInternal: true` for audit-style hooks.
- **The auth path comes from better-auth** (a `baseURL` path beats `basePath`), not from `auth.options.basePath`. Check that the client's `baseURL` agrees.
- **The rate-limit IP comes from the platform** (`trust proxy` / `trustProxy`). Configure it behind a proxy (checklist step 8).
- **Unprotected surfaces now fail boot.** This covers WebSocket gateways without `@UseBetterAuth()` on both majors, hybrid RPC handlers without `inheritAppConfig`, guarded GraphQL field resolvers without `fieldResolverEnhancers: ['guards']`, controller routes with library decorators under `globalGuard: false`, and handlers with library decorators that no registered transport serves. Fix them, or mark them `@Public()`.
- **On Fastify:**
  - `@fastify/cors`, helmet and `onSend` hooks now apply to auth routes, and auth-route failures reach your global exception filters;
  - the app's JSON parser is Fastify's secure one again (the reference had replaced it and dropped proto-poisoning protection);
  - the `qs` optional peer is no longer needed.
