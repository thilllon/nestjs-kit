# nestjs-slightly-better-auth — Design Review Ledger

This ledger tracks the review history of the `nestjs-slightly-better-auth` design document. Design v1 (`design-v1.md`) was produced by the lead architect by merging three independent drafts (A: thinnest faithful host binding with a mandatory `nestjs()` plugin; B: ports-and-adapters with a DI composition root and conformance kits; C: DX-and-types-first with a `Register` augmentation and boot checks), verified against better-auth 1.7.4 and NestJS 11/12 source. Each later review round appends an entry here recording the reviewer, the findings raised (with severity and the affected design sections), the resolution chosen for each finding (accepted, rejected with rationale, or deferred to an open question), and the resulting document version, so that every change to the design stays traceable to a specific finding.

## Round 1 → design v2 (2026-09-11)

Reviewers: **BA** (better-auth fidelity), **NEST** (NestJS correctness, packaging, SOLID), **SEC** (security/SRE). All three verdicts: _reject_. Input: `design-v1.md`. Output: `design-v2.md`. Prior-finding statuses: none (first review round; no earlier findings existed to re-check).

Lead verification for this round: LEAD-V16–V32 (source re-checks) and LEAD-EXP-2–4 (`tmp-revise-v2/`): Fastify child error handler on Nest 11.1.17/12.0.1 × both bootstraps with a global prefix; last-arrival mount coordinator incl. adapter-less bootstraps; Node 22 `fetch` browser-signal headers. Reviewer experiments were re-run where they decided an action (REV-NEST exp1, exp3b). The revision was interrupted and finished on 2026-09-17 (`tmp-finish-v2/`). The finishing pass added LEAD-V33 (the better-auth surfaces v2 depends on exist at the 1.7.0 floor; better-auth's own origin rule gained the `Origin: null` + `Sec-Fetch-Site: same-origin` inference only in 1.7.2), LEAD-EXP-5 (a subpath's declaration file can augment `PrincipalKinds` of the root specifier by package self-reference; TypeScript 5.9, 6.0, 7.0 × four resolution modes) and LEAD-EXP-6 (scrubbing an error's message in place still leaks Drizzle's enumerable `params`). A post-revision audit against this ledger then found gaps, and closing them added LEAD-V34 (guards and interceptors share the `args` array on GraphQL, RPC and WS, but not on HTTP), LEAD-V35 (Mercurius copies the context per subscription start) and LEAD-EXP-7 (GraphQL drivers send a thrown error's `message` and `extensions`, not its other own properties). Each note below ends with the ADR that records the decision (design §16).

## Round 2 → design v3 (2026-09-17)
